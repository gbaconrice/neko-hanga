# 後半の制限時間ルール: 式だけで測った結果（モデルによる見積もり）

**これは人のプレイテストでも実機での計測でもありません。** ゲームの式に「仮のプレイヤー」をあてて数えた見積もりです。プレイヤーの速さ・ばらつき・ミスの確率はすべて仮定（モデル）で、人のデータではありません。

## 表記

- **n** = すでに刷れた枚数（コードの `prints`。`cfg(n)` に渡す値）。
- **何枚目** = いま挑戦している紙 = n+1。表では「n=44（45枚目）」のように両方書きます。
- 「45枚目」「60枚目」は n=44・n=59 です。n=45・n=60（46枚目・61枚目）も載せています。
- 判定の締め切りを広げる処理（`GRADE_FIT`）は tier 2 から効きます。tier 2 は n=7、つまり **8枚目から**です。n=6（7枚目）までは新旧で同じ値になります。

## 比べたもの

- **新ルール**: このブランチ（PR #16 の head `bff0165`）の index.html。
  - 制限時間 = `max(sheetTime, TIME_FIT(n)×最速 + TIME_PAD)` + 持ち越し
  - 締め切りは経過秒で決めます。うっとり = `max(0.45×制限, 2.0×最速+1.0)`、めろめろ = `max(0.2×制限, 1.3×最速+0.5)`（それぞれ制限時間や、うっとりの締め切りを上限にします）
- **旧ルール**: main の `027575c` の index.html。
  - 制限時間 = `sheetTime` + 持ち越し
  - 判定は残り時間の割合で決めます。0.8 以上でめろめろ、0.55 以上でうっとり
- `cfg` と紙の生成コードは、新旧で文字まで同じでした（スクリプトで確かめています）。違うのは制限時間と判定の式だけです。

## 方法

- 再実行: `node scripts/measure/sim.cjs`（約30秒、乱数の種は固定）。同じ条件なら同じ結果が出ることを、2回実行して確かめました。ファイルを書き出さずに速く試すには `--quick`（紙・プレイとも300）を付けます。
- 出力:
  - `docs/measure/sim-tables.md`: 全部の表（自動生成）
  - `docs/measure/sim-results.json`: 数値、抜き出したコード片、自己確認の結果
- **コードの読み方**: 定数の行、`cfg`・`sheetTime`・`TIME_FIT`・`bestTime`・`rnd`・`shuffle` は、index.html の本文から正規表現で抜き出し、Node の `vm` の中で評価しています（定数を手で写していません）。旧ルールは `git show 027575c:index.html` から同じ方法で抜き出しました。次のコード片も、本文から抜き出したものをそのまま実行しています。
  - `newSheet` の紙の生成（`var mov=shuffle…` から `var sol=…` まで）、制限時間と締め切りの4行、ラストチャンスの紙
  - `variant` の特色の抽選
  - `onPrint` の frac・判定・取り返し・倍率・記念・得点・フィーバー・復活・持ち越し・回復の文
  - `onTimeout` とミスのときの文、`startLast`、`canLast`
- **自己確認**: 抜き出した生成コードとは別に、同じ処理を手で写した版（`sim.cjs` の `mirrorGen`、写した元の行はコメントに書いてあります）も用意しました。同じ乱数の種で比べると、5500 枚すべてで一致しました。
- **手で写した部分**: 分岐の流れだけです（成功・ミス・時間切れのどれになるか、肉球が0になったら `canLast` ならラストチャンス・そうでなければ終わり、ミスのあとは同じ紙を続ける）。`sim.cjs` の `playRun` のコメントに書いてあります。乱数を引く順番は実物と違います（分布は同じ）。
- **プレイヤーのモデル**:
  - 1枚にかかる時間 T = k × bestTime（元の OP_* 定数で計算）× exp(σ·z)。z は標準正規分布なので、ノイズの中央値は1です。
  - k は 0.7（速い）、1.0（ゲームが想定する最速どおり）、1.4（遅い）、2.0（とても遅い）。σ は 0.25（標準）と 0.4 の2通り。
  - ミス（ずれたまま刷る）は1枚につき確率 0.05 で1回だけ、T の途中の一様に選んだ時点で起きるとしました。
  - 新旧どちらのルールにも、同じ人（同じ紙・同じノイズ）をあてています。
- **数えていないもの**:
  - おたすけ（使わないものとしました）
  - 1枚目の「触るまで時間が止まる」こと
  - 演出中の待ち時間
- **★特色**: `RARE_ONE_IN` の抽選どおり入れています（SP_PT 加点）。
- **件数**:
  - 1枚ごとの表: n ごとに種 1..2000 で 2000 枚。持ち越しなし、ミスなし、倍率なし。
  - 通しの表: k ごとに 2000 回（種 1..2000）、上限 120 枚。
  - n は {6, 7, 11, 12, 17, 18, 24, 25, 26, 30, 35, 44, 45, 59, 60}。

## 読み取り（モデルの仮定のもとで）

1. **めろめろの割合は、8枚目以降ほぼ一定で、人の速さ k だけで決まります。** 新ルールでは、k=1.0 で約87%、k=1.4 で約42%、k=0.7 で約99%、k=2.0 で約5% です。n にはほとんどよりません（σ=0.25）。めろめろの締め切りが「1.3×最速+0.5」なので、最速の見積もりどおりに動ける人（k=1.0）はほとんどめろめろになります。旧ルールでは、18枚目以降の k=1.0 のめろめろはほぼ 0% で、45枚目・60枚目では k=1.0 でも 34〜38% が時間切れでした。
   - **やさしすぎる側**: k≤1.0 では、後半でもめろめろが「ふつう」になります（87〜99%）。
   - **むずかしすぎる側**: k=2.0 のめろめろは約5%で、旧ルールの 0% からはほぼ変わりません。代わりに時間切れが大きく減りました（45枚目で 99%→19%）。
2. **ゲームが終わりにくくなっています。** 新ルールでは、k≤1.0 なら後半でも時間切れが 0〜0.1% です。肉球を失うのはほぼミスだけになり、5枚続けて刷ると回復するので、98% のプレイが120枚の上限まで続きました。後半は `TIME_FIT` が n=60 で 2.0 に下げ止まったあと、それ以上厳しくなりません（制限 ≈ 2×最速+4 ≈ 41秒、最速 ≈ 18.7秒）。時間切れが増えるのは k が 2 近く、またはばらつきが大きい人だけです。
3. **得点の水増し**: 得点の中央値の新/旧は、k=1.0 で約2.8〜3.1倍、k=1.4 で約3.3〜3.8倍、k=2.0 で約1.3〜2.1倍でした。k=0.7 は新旧とも上限に届くので 1.1〜1.4倍です。上限で打ち切っているので、本当の比はこれより大きいはずです。主な理由は、長く続くこと（枚数が増える）と、はやさ点・連続倍率・フィーバーが続きやすいことです。
4. **前提の影響**: 結論にいちばん効くのは OP_LINK と OP_KNOB です。±30% で、k=1.0 のめろめろは 73〜94% のあいだで動き、k=2.0 の到達枚数の中央値は 31〜67 のあいだで動きます。OP_STEP は中くらいで、OP_LOOK・OP_PRINT はほとんど効きません。つまり「連動1つ・つまみ1つに人が実際に何秒かかるか」が、結論の確かさを決めています。

## 調整の案（提案だけ。コードは変えていません）

- **めろめろを「上手な人のごほうび」に戻したいとき**: `GRADE_FIT` のめろめろの倍率（いまは 1.3）を **1.0〜1.2** にする案があります。後半（最速 ≈ 18.6秒）の k=1.0・σ=0.25 のめろめろは、倍率 1.2 で約79%、1.1 で約68%、1.0 で約54% になる見込みです。これは同じモデルの式 P(z ≤ ln(倍率+0.5/最速)/σ) から出した値で、通しのシミュレーションでは確かめていません。この式でいまの 1.3 を計算すると約87%で、表と合います。採用するなら、定数を変えて同じスクリプトを回して確かめてください。
- **ゲームが終わるようにしたいとき**: `TIME_FIT` が n≥60 で 2.0 に張り付いたままなのを見直す案があります。たとえば 61枚目以降もゆっくり下げて、**1.6〜1.8 前後**を下限にする案です。ただし、うっとりの締め切り（2×最速+1）は制限時間を上限にしているので、下げすぎるとごろごろの幅がなくなります。
- どちらの案も、先に **連動1つ・つまみ1つの実測（OP_LINK・OP_KNOB）** を人の操作で取ってから決めるのが安全です。いまの結論は、その2つの定数への依存が大きいからです。

## 限界

- プレイヤーはモデルです。
  - k、σ、ミス確率 0.05、ミスが1枚1回までという設定は、どれも仮定です。
  - 慣れによる上達、疲れ、紙の種類ごとの苦手は入れていません。
  - 人の操作時間が bestTime に比例するという前提そのものが、まだ確かめられていません。
- 数えていないもの:
  - おたすけ
  - 1枚目の「触るまで止まる」時間
  - 演出の待ち時間
  - フレームごとの時間の進み方（`dt` の上限 0.1秒など）
- 1枚ごとの表は、持ち越しなし・ミスなしの条件です。通しの表には持ち越しが入っています。
- 通しの表は上限120枚で打ち切っています（上限に届いたプレイの得点と枚数は、実際より小さく出ます）。
- 実機・ブラウザでは確かめていません（ブラウザでの確認は別の担当の `browser-results.md` を参照してください）。
