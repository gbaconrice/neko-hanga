# 後半の制限時間と判定：計測のまとめと調整案

対象は PR #16（`bff0165`）の決まりです。この文書は計測と提案だけで、ゲームの仕様は変えていません。

- **枚数の書き方**：n は刷り終えた枚数（コードの `prints`）、「何枚目」はいま挑戦している紙（n+1）です。例：n=44（45枚目）。判定の延長が効き始めるのは n=7（8枚目）からです。
- **計測は2種類あり、どちらも人の試遊ではありません**
  - 机上（式だけ）：`docs/measure/sim-results.md`。遊ぶ人をモデルで置いた試算です。
  - ブラウザ（実際の画面をタッチで自動操作）：`docs/measure/browser-results.md`。自動操作の速さで、見て考える時間を含みません。
- **未確認**：iPhone実機、GRAVITY、人の操作時間。

## 分かったこと

1. **締め切りに届かない紙はない（ブラウザ・実際の画面）**
   - 実際の画面を自動で最速に操作すると、指の動きだけなら後半でも4〜6秒で終わりました。110枚すべてめろめろでした。
   - 最速の見積もり（後半18〜19秒）との差の約13〜14秒は、「つまみ1つを見て判断する時間」（`OP_KNOB`）と「連動を合わせ直す時間」（`OP_LINK`）の仮定です。
   - 締め切りが人にとって妥当かどうかは、この仮定で決まります。人の試遊でしか確かめられません。

2. **#16 の決まりでは、後半でほとんど終わらなくなる（机上）**
   - 遊ぶ人の速さが見積もりの1.4倍以内なら、後半でも時間切れはほぼ起きません。
   - 肉球はミスだけで減り、5枚続けて刷ると1つ戻ります。そのため、上限を200枚にした試算でも、見積もりどおりの速さ（k=1.0）の人の97%が上限まで続きました。
   - main の旧ルールでは、同じ人の中央値は49枚です。旧ルールは、後半の制限時間が最速の見積もりより短くなって終わっていました。ユーザーの「理屈上無理」は、これを指していました。

3. **得点の膨らみ**
   - 1枚あたりの増え方は小さいです。はやさ点は最大100点で頭打ちです。
   - 総得点は、続けられる枚数が増えるぶん大きく膨らみます。上限200枚で、k=1.0 の中央値は旧ルールの約4.8倍です。上限で打ち切っているので、実際はもっと大きくなります。

4. **めろめろの取りやすさは、遊ぶ人の速さでほぼ決まる（机上）**
   - 8枚目以降、めろめろの割合は、k=1.0 で約87〜90%、k=1.4 で約45%、k=2.0 で約10%でした。
   - 仮定を±30%動かしたとき、結果を大きく変えるのは `OP_LINK` と `OP_KNOB` です。`OP_LOOK` と `OP_PRINT` はほとんど効きません。

## 調整案（試算のみ。決まりは変えていない）

### 案A：60枚目より先も制限時間を締めていき、終わりのある形に戻す

判定の締め切り（めろめろ・うっとり）はそのままにします。制限時間の倍率 `TIME_FIT` だけを、後半も下げ続けます。倍率1.0は「最速の見積もり＋4秒」です。

比較した倍率の式は `scripts/measure/variants/` にあります。条件は、σ=0.25、通しのプレイ1000回、上限200枚、ミス率5%です。

| 倍率の決まり | k=1.0 枚数の中央（上限到達） | k=1.4 枚数の中央 | k=2.0 枚数の中央 | k=1.0 得点の中央 |
|---|---|---|---|---|
| main（旧ルール） | 49（0%） | 37 | 26 | 24,351 |
| #16 の現行（下限2.0） | 200（97%） | 200（85%が上限） | 48 | 116,526 |
| v2：35〜75枚で2.4→1.5 | 200（97%） | 93 | 47 | 113,535 |
| v4：60枚まで#16と同じ、そこから80枚で1.0 | 107（3%） | 77 | 48 | 58,138 |
| **v5：35〜75枚で2.4→1.0** | **100（3%）** | **69** | **45** | **54,094** |

- 下限が1.5でも、まだほとんど終わりません（v2）。終わりのある形にするには、倍率を1.0近くまで下げる必要があります。
- **候補は v5** です。理由は2つあります。
  - 35枚目までは #16 と同じで、後半の「時間が足りなすぎる」は解消したままです。
  - 75枚目より先は、最速の見積もりに4秒足した長さになるので、「理屈上無理」には戻りません。
- 速い人（k=0.7）は、どの案でも上限まで続きます。旧ルールでも81%が上限に届いていました。
- 1回の遊びの長さは、決める必要があります。k=1.0 で100枚は、1枚15〜20秒として約30分です。もっと短くしたい場合は、下がり始める位置を早めます。

### 案B：めろめろの取りやすさは、人の操作時間を測ってから決める

- 試算上、k=1.0 の人のめろめろが約9割で、取りやすすぎる可能性があります。
- ただしそれは、`OP_KNOB` と `OP_LINK` が人の実際に近い場合の話です。先にここを人で測ります。
- 測る方法の案（いずれも新しい機能になるので、提案だけ）：
  1. 簡単な方法：2〜3人に後半まで遊んでもらい、画面を録画します。紙ごとに「つまみの数・連動の数・かかった秒数」を読み取ります。
  2. 正確な方法：`?debug=1` のときだけ、紙ごとの経過秒と最速の見積もりを結果画面に一覧で出します。保存はしません。
- 測った結果で、`OP_KNOB` と `OP_LINK` を合わせ直します。めろめろの倍率（1.3）は、合わせ直したあとも取りやすすぎる場合だけ、1.1〜1.2に下げます。

## 再実行

```
node scripts/measure/sim.cjs                         # 机上の計測（約30秒、結果を docs/measure/ に書き出す）
node scripts/measure/sim.cjs --runs 1000 --seeds 300 --cap 200 --variant scripts/measure/variants/v5.js   # 案の試算（書き出さない）

```
