# 計測版(人の試遊の時間を測る)

## 目的

後半の紙(45枚目・60枚目など)を、人が実際に遊ぶとどれくらいかかるかを測るための道具です。
公開しているゲーム(index.html)から「計測版」のコピーを作り、手元のブラウザで1枚ずつ遊んで、時間をメモリに記録します。

- 公開しているゲームは変えません。index.html は読むだけです。
- 計測版のHTMLはコミットしません(`playtest/out/` は .gitignore 済み)。GitHub Pages には載りません。
- 自動テスト(`tests/playtest.cjs`)は**自動のスモークテスト**です。人の計測ではありません。テストで出る時間を、人の時間として使わないでください。

## 作り方・開き方

```sh
node scripts/playtest/build.cjs
```

`playtest/out/harness.html` ができます(約12MB)。開き方はどちらでもかまいません。

- ファイルをそのまま開く: `playtest/out/harness.html` をブラウザで開く(file://)
- 手元で配信する: `cd playtest/out && python3 -m http.server 4176` → `http://127.0.0.1:4176/harness.html`

計測版の上部には、元にしたコミットと index.html の sha256 が出ます。書き出した記録にも1件ずつ入ります。
index.html にコミットしていない変更があるときは「未コミットの変更あり」と出ます。

## 1回の流れ

1. 「挑戦する紙」に枚目を入れる(45 / 60 のボタンもあります)。下に「刷り済み n=…」が出ます。45枚目は n=44 です(ゲームの `cfg(n)` は、すでに刷った枚数 n を使うため)。
2. 「種(seed)」はそのままでかまいません(開いたときに乱数で決まり、画面に出ています)。同じ種と同じ枚目なら、まったく同じ問題(絵・つまみ・連動・正解・制限時間)になります。
3. 「記録する人」に名前や記号を入れます(このページの中だけに残ります)。
4. 「この問題で開始」を押すと、その紙だけを1枚遊びます。上に小さく「挑戦中 45枚目（刷り済み n=44）」と出ます。
5. 刷る(成功・ミス)、時間切れ、または「中断」で1回が終わり、パネルに戻ります。次の紙には進みません。
6. 「同じ問題をもう一度」は同じ種・同じ枚目、「別の問題」は新しい種で始めます。
7. 終わったら「結果をコピー」(JSON)か「JSONを書き出し」(ファイル)で取り出します。押さない限り、記録はどこにも出ません。ページを閉じると消えます。「記録を消す」は2回押すと消えます(メモリの中だけ)。

「初見」はこのページで初めてその種・枚目を遊んだ回、「反復 k回目」は同じ種・枚目の k 回目です(中断した回も数えます)。

パネルを畳むとタイトル画面が見えますが、そこの「はじめる」は普通のゲームで、計測しません(ランキング送信もしません)。

## 1回の条件(後半の普通の紙にそろえる)

毎回、ゲームを最初から始め直してから、すぐにその枚目へ飛びます。そのうえで:

| 項目 | 計測版での扱い | 記録名 |
|---|---|---|
| 肉球 | 3 | `lives` |
| 前の紙からの持ち越し時間 | 0 | `carry` / `lastCarry` |
| 連続・フィーバー | 0(倍率なし) | `streak` / `fever` / `feverGauge` |
| 最初の紙だけの「触るまで時間が止まる」 | 切る(紙が操作できた時から時間が進む) | `waitTouch.active=false`、本来あったかを `waitTouch.wouldHaveBeen` |
| 紙替わり直後の「刷る」受け流し(PR#13、0.4秒) | **そのまま有効** | `tapGuardMs=400` |
| 画面切り替え直後の、つまみの受け流し | 切る(後半の紙は画面切り替え直後ではないため) | `knobScreenGuardCleared=true` |
| 操作の案内文 | 出さない(後半ではもう見たものとして扱う) | — |
| ★特色 | 種に従う(出るかどうかも種で決まる) | `rare.mode='seed'`、出たかを `rare.rare` |
| おたすけ | ゲーム開始時と同じ1回 | `helpsAtStart`、使ったら `helpTaps` |

問題の作り方・つまみの操作・判定・制限時間は、ゲームそのもののコードです。
変えているのは「絵と乱数を種から決める」ことだけです(`newSheet()` の問題を作る数行の間だけ、`Math.random` を種つきの乱数 mulberry32 に差し替え、すぐ戻します。絵も種から選びます)。

## 記録される時刻と区間

時刻は「開始」を押した瞬間を0としたミリ秒(`performance.now()`)です。並べ替え用に開始時の時計(`epochStart`)も入ります。

| 時刻 | 意味 |
|---|---|
| `t_operable` | 紙が操作できるようになった(ゲームの busy が外れた)。制限時間はここから減ります |
| `t_ready` | 「表示」。紙の入場アニメ(`.paper.pin`、0.24秒)が終わった時刻。Web Animations API でその CSS アニメの終わり(またはゲームのタイマーで外された時)を待って記録します。アニメがない環境では `t_operable` と同じです。方法は `readyMethod` に入ります |
| `t_firstInput` | 最初に受け付けられたつまみの押下(またはおたすけ) |
| `t_lastInput` | 刷る前の最後のつまみの指離し(またはおたすけ)。弾いて回った分が止まった時刻は `t_lastSettle` |
| `t_print` | 「刷る」が受け付けられた時刻(受け流された押下は含めない) |
| `t_judge` | 判定が見えた時刻(成功: 判定の札が出た時、ミス: 「おしい」などが出た時、時間切れ: 時間が切れた時) |
| `t_nextReadyWouldBe` | 普通のゲームなら次に操作できたはずの時刻。成功・時間切れは「次の紙を作り始めた時刻＋入場アニメ0.24秒」の**見積もり**(次の絵を読み込む時間は含まない)。ミスは同じ紙がまた操作できるようになった時刻の実測。方法は `nextReadyMethod` に入ります |

区間(名前はわざと中立にしています):

| 区間 | 計算 | 言えること | 言えないこと |
|---|---|---|---|
| A「表示→最初の入力」 | `t_firstInput − t_ready` | 紙が見えてから最初に指が触れるまで | **純粋な「考える時間」ではありません**。手を伸ばす時間も入りますし、考え終わる前に触る人もいます |
| B「最初の入力→最後の入力」 | `t_lastInput − t_firstInput` | 触り始めてから最後に指を離すまで | **純粋な「操作の時間」ではありません**。途中で見て考えている時間が混ざります |
| C「最後の入力→刷る」 | `t_print − t_lastInput` | 合わせ終えてから刷るまで | 確かめている時間か迷っている時間かは区別できません |
| D「刷る→判定」 | `t_judge − t_print` | ゲームの演出の時間(ほぼ一定) | 人の時間ではありません |
| 演出待ち | `t_nextReadyWouldBe − t_judge` | 普通のゲームなら次の紙まで待つ時間 | 完成図をタップで早送りした場合は短くなります |

ほかに: 結果(めろめろ／うっとり／ごろごろ／ミス／時間切れ／中断)、ゲーム内で使った秒(`gameTimeUsedS` = 制限時間 − 刷った時の残り)、紙の情報(作品番号、つまみの種類、連動の数、つまみごとの必要な目盛り数とその合計、最速の見積もり `best`、`tMax`・`dM`・`dU`)、画面の大きさ・DPR・UA・動きを減らす設定・使われた入力の種類。

入力の記録(`inputs`)は、つまみごとに 押した・離した時刻、押していた長さ、回した角度と目盛り数、種類(tap／drag／fling／long-press(0.5秒以上)／cancel)、受け付けられたか。
「刷る」の押下(`printTaps`)は、受け流されたもの(`reason: tap-guard` など)も残します。

最初の入力が `t_ready` より前(入場アニメ中)だったときは `inputBeforeReady=true` になり、区間Aは負になります。

## 切り離しの保証と、その確かめ方

計測版のコピーにだけ、次のことをしています(index.html は変えません)。

- **通信しない**: `default-src 'none'` の CSP(`connect-src 'none'`、画像・音・フォントは埋め込みの data: だけ許可)を、最初のスクリプトより前に置きます。GRAVITY の SDK の `<script src>` は取り除きます。
- **ランキングへ送らない**: `sendScore()` の `postMessage` を、メモリに「送るはずだった」と残すだけに置き換えます(画面上部に件数が出ます)。
- **保存しない**: 動作確認画面の保存の試し書きを取り除きます。さらに、ゲームより先に見張りを入れ、Storage の setItem/removeItem/clear、cookie への書き込み、IndexedDB を開くことを、何もせずに記録だけするようにしています。
- 生成スクリプトは、差し替えの目印がちょうど1回ずつあることを確かめ、なければ止まります。仕上がりに `gravity.place`・`postMessage`・`localStorage` などが残っていたら止まります。

`tests/playtest.cjs`(自動スモーク)で確かめていること:

1. リクエストは計測版のHTMLだけ。わざと出した `fetch('https://example.com')` と画像の読み込みは CSP で止まる。
2. ミス・時間切れ・普通のゲームオーバーを通しても、`gameOver` の message は0件、`postMessage` の呼び出しも0回。SDK は読み込まれない。
3. 試行のあと localStorage・sessionStorage は空、setItem は一度も呼ばれない、IndexedDB のデータベースなし、cookie は空。
4. 同じ種＋n=44 を2回、ページを読み込み直したあと、file:// で開いたときも、同じ作品・つまみ・連動・正解・制限時間。違う種なら違う問題。n=59(60枚目)でも動き、「45枚目（刷り済み n=44）」「60枚目（刷り済み n=59）」と出る。
5. 本物のつまみにタッチで指回し・タップをして合わせ、刷る。時刻の順序(表示 ≤ 最初の入力 ≤ 最後の入力 ≤ 刷る ≤ 判定)、区間、結果、早すぎる「刷る」が受け流しとして残ること(テストは正解をゲームから直接読んで合わせています。計測版の画面は正解を出しません)。
6. 画面に正解が出ない。自動で合わせるボタンがない。記録にも正負つきの正解は入れない。
7. index.html が計測版を参照しない。`playtest/out` は .gitignore 済み。目印が欠けた・2つある index.html では生成が失敗する。`PLAYTEST_BASE=<コミット>` を付けると、そのコミットから index.html が変わっていないことも確かめる。
8. 「結果をコピー」「JSONを書き出し」の中身に、コミット・種・n・枚目・時刻が入っている。
9. 320×568 と 390×844 でパネルが横にはみ出さず、挑戦中の表示が紙に重ならない。

手元での実行: `node scripts/playtest/build.cjs && CHROMIUM_PATH=/usr/bin/google-chrome node tests/playtest.cjs`

## 限界

- 自動スモークの時間は人の時間ではありません。人の計測は、人が計測版で遊んだ記録だけです。
- iPhone や GRAVITY の中での動き・時間は、そこで計測版を開いて遊ばない限り分かりません。手元のブラウザでの記録は、手元の端末での記録です。
- 区間A・Bには判断と操作が混ざっています。「考える時間」「操作の時間」を切り分けたものではありません。
- 毎回ゲームを始め直してすぐ後半の紙へ飛ぶので、それまでの44枚で手が慣れている状態や、前の紙からの持ち越し時間・連続の倍率は再現しません(上の表のとおり固定)。
- `t_nextReadyWouldBe`(成功・時間切れ)は見積もりで、次の絵の読み込み時間を含みません。
- 見張りは Storage の関数呼び出しを止めますが、`localStorage.foo = …` のような直接の代入は止められません(ゲームにはその書き方がなく、生成時にゲーム側に `localStorage` の文字が残っていないことを確かめています)。
- テスト用の `window.__pz`(デバッグ用の窓口)は計測版では常に有効です。開発者ツールから正解を読むことはできてしまいます(画面には出しません)。
